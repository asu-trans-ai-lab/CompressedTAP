# Data inventory

Network + demand inputs are committed; large path-pool (column) files are NOT — they
regenerate deterministically from these inputs. LFS is used only for files > ~5 MB
(see `.gitattributes`; run `git lfs install` once before cloning).

| directory | contents | LFS | notes |
|---|---|---|---|
| `chicago_regional/` | node/link/demand + GMNS aux; top-20k demand subset | link.csv, demand.csv | pools excluded; see its README for regeneration |
| `chicago_sketch/` | node/link/demand + GMNS aux; `columns.csv` (earlier campaign) | no | 11 pool files (30–160 MB) excluded; K10/K15 regenerate via `ksp_gen` (below) |
| `submitted_v2/sketch/`, `submitted_v2/sioux/` | the COMPLETE submitted-paper instances, pools included | sketch/pool.csv | provenance data — the exact instances of the OR submission; do not regenerate, keep verbatim |
| `two_corridor/` | small demo instance | no | |

## The grid family needs no data files

Every grid instance (exp03/exp04/exp08-11 heritage) is generated by code committed in
this repo: `campaign_weighted/drivers/exp03_grid.py::gen_grid` builds node/link/demand,
and `ksp_gen` builds its pools. Nothing to download.

## Regenerating excluded Sketch pools

```bash
# K-shortest-path pools (deterministic penalty method, factor 1.4)
stable_release/10_implementation/ksp_gen.exe data/chicago_sketch 10 1.4 path_pool_K10.csv
stable_release/10_implementation/ksp_gen.exe data/chicago_sketch 15 1.4 path_pool_K15.csv
```

E0/E1/E2/GEN* pools came from earlier enrichment pipelines (see `repro_v3/`); the
campaign's certified results identify which pool each number used.

## Regenerating the exp12/exp13 nested extreme-case pools

```bash
python campaign_weighted/drivers/exp12_gen_pools.py --net sketch   --M 20000 --K 64 --ratio 2.5
python campaign_weighted/drivers/exp12_gen_pools.py --net regional --M 20000 --K 64 --ratio 2.5
```
